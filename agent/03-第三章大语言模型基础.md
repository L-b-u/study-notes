# 第三章：大语言模型基础

参考资料：Datawhale `Hello-Agents` 第三章《大语言模型基础》。

## 一、这一章要解决什么问题

前两章回答了“什么是 Agent”和“Agent 从哪里发展而来”，这一章进一步回答：

```text
Agent 里的 LLM 到底是什么？
它如何理解和生成文本？
为什么 Transformer 成为主流？
我们如何正确地和模型交互？
模型为什么会犯错，应该如何降低风险？
```

建议把本章看成四条主线：

1. 语言模型的演进：`N-gram → RNN/LSTM → Transformer`。
2. 文本如何进入模型：`Tokenization → Embedding → 模型计算`。
3. 模型如何被使用：Prompt、生成参数、模型选型和本地部署。
4. 模型能力和边界：缩放法则、涌现能力、幻觉与可靠性。

## 二、语言模型是什么

语言模型的基本任务是估计一段词序列出现的概率，并根据已有上下文预测下一个词：

```text
输入：智能体可以调用
预测：工具
```

一个句子的概率可以用链式法则表示：

```text
P(w1, w2, ..., wm)
= P(w1) × P(w2 | w1) × ... × P(wm | w1, ..., w(m-1))
```

现代语言模型在生成文本时，本质上也是不断执行：

```text
根据已有 Token 计算下一个 Token 的概率分布
→ 选择一个 Token
→ 把它加入上下文
→ 继续预测下一个 Token
```

这解释了为什么模型生成是逐步进行的，也解释了为什么上下文、生成参数和停止条件都会影响最终结果。

## 三、从 N-gram 到神经网络

### 1. N-gram 和马尔可夫假设

完整的历史上下文太难估计，因此 N-gram 使用马尔可夫假设：一个词只依赖前面有限个词。

- Bigram：`P(w_i | w_(i-1))`
- Trigram：`P(w_i | w_(i-2), w_(i-1))`

Bigram 概率可以通过计数估计：

```text
P(下一个词 | 当前词)
= Count(当前词, 下一个词) / Count(当前词)
```

N-gram 的问题：

- **数据稀疏**：没有见过的词序列概率可能直接变成 0。
- **上下文有限**：只能看到固定数量的前文。
- **缺少语义泛化**：把词当成离散符号，难以理解 `agent` 和 `robot` 可能语义相近。
- **参数规模增长快**：上下文窗口变长后，需要统计的组合数量快速增加。

### 2. 词嵌入和神经网络语言模型

神经网络语言模型把离散词映射成连续向量，也就是词嵌入（Embedding）。语义相近的词有机会在向量空间中靠近，模型因此能够进行一定程度的泛化。

词向量之间常用余弦相似度衡量关系：

```text
cos(a, b) = (a · b) / (|a| |b|)
```

需要注意：词嵌入不是“字典里的固定解释”，而是模型为了完成预测任务学习出来的参数表示。

### 3. RNN 和 LSTM

RNN 通过隐藏状态保存序列信息：

```text
当前输入 + 上一个隐藏状态 → 当前隐藏状态
```

它比固定窗口的 N-gram 能够保留更长的历史，但长序列训练时容易出现梯度消失或梯度爆炸，导致长期依赖难以学习。

LSTM 在 RNN 基础上增加细胞状态和门控机制：

- 遗忘门：决定丢弃哪些旧信息。
- 输入门：决定写入哪些新信息。
- 输出门：决定当前输出哪些信息。

RNN/LSTM 的主要问题是必须按顺序计算，难以充分并行，序列很长时速度和扩展性受限。这为 Transformer 的出现铺平了道路。

## 四、Transformer 为什么重要

Transformer 在 2017 年提出，核心变化是：

```text
不依赖循环结构，而是用注意力机制直接建模序列中不同位置的关系
```

因此它可以对同一序列中的多个位置进行并行计算，并且更容易捕捉长距离依赖。

### 1. Encoder-Decoder 结构

最初的 Transformer 用于机器翻译，采用编码器—解码器结构：

- **Encoder**：理解完整输入，为每个 Token 生成带上下文的表示。
- **Decoder**：根据已经生成的内容和 Encoder 输出，逐步生成目标序列。

Decoder 中的交叉注意力可以让它参考 Encoder 对输入的理解。

### 2. 自注意力机制

自注意力让每个 Token 在生成新的表示时，都可以关注序列中的其他 Token。例如理解句子中 `it` 指代什么时，可以关注前面的名词。

每个输入向量会通过三个可学习矩阵生成：

- `Q`（Query）：我想查询什么。
- `K`（Key）：我具有什么可被匹配的特征。
- `V`（Value）：我真正携带的内容。

缩放点积注意力公式：

```text
Attention(Q, K, V)
= softmax(QK^T / sqrt(d_k))V
```

理解公式只需要抓住四步：

1. 用 `Q` 和 `K` 的点积计算相关性。
2. 除以 `sqrt(d_k)`，避免数值过大。
3. 用 Softmax 将分数转成注意力权重。
4. 用权重对 `V` 加权求和。

### 3. 多头注意力

多头注意力把 `Q、K、V` 分成多个头，每个头在不同表示子空间中独立计算注意力，再拼接并线性变换。

```text
一个头：关注一种关系
多个头：同时关注指代、语法、位置、语义等不同关系
```

### 4. 位置编码

注意力本身不天然知道 Token 的先后顺序。位置编码把位置信息加入 Token 表示，使模型能够区分：

```text
“猫追狗” 和 “狗追猫”
```

因此 Transformer 既能并行处理 Token，又不能丢失序列顺序。

### 5. 残差连接、层归一化和前馈网络

Transformer 层通常还包含：

- **残差连接**：保留原始输入，帮助深层网络训练。
- **层归一化**：稳定不同层的数值分布。
- **前馈网络**：对每个位置的表示进行进一步非线性变换。

可以把一个 Encoder 层粗略记成：

```text
输入 → 多头自注意力 → 残差与归一化 → 前馈网络 → 残差与归一化
```

## 五、Decoder-Only 为什么成为主流

现代 GPT 类大语言模型通常采用 Decoder-Only 架构，使用因果掩码保证当前位置不能看到未来 Token：

```text
只能根据左侧已经出现的 Token 预测下一个 Token
```

它的优势是训练目标统一、架构简单、容易扩展到大规模生成任务，也能通过 Prompt 统一处理问答、代码、总结和工具调用。

Encoder-Decoder 更适合输入和输出边界清晰的转换任务，例如翻译；Decoder-Only 更适合通用自回归生成，因此成为当前通用 LLM 的主流架构之一。

## 六、Tokenization：文本如何进入模型

模型不能直接读取中文字符、英文单词或整段字符串，必须先将文本切分成 Token，再把 Token 映射成整数 ID。

```text
原始文本 → Tokenizer → Token ID 序列 → Embedding 向量 → Transformer
```

### 1. 为什么不直接使用字符或单词

- **字符级**：词表小，但序列很长，模型需要处理更多位置。
- **单词级**：英文中词表巨大，遇到新词、拼写变化和中文分词时不灵活。
- **子词级**：在词表大小和序列长度之间折中，既能复用常见片段，也能组合出未见过的词。

### 2. BPE 的基本思想

BPE（Byte Pair Encoding）从较小的基本单元开始，反复合并语料中最常见的相邻片段，最终得到子词词表。

它解决了两个问题：

1. 常见词或词片段可以作为一个 Token，减少序列长度。
2. 生词可以拆成已知子词，降低完全无法处理的情况。

Token 不等于字符，也不一定等于单词。不同模型的 Tokenizer 不同，同一段文本的 Token 数也可能不同，这会影响上下文长度、推理速度和 API 费用。

## 七、Prompt Engineering

Prompt 是给模型的输入指令。模型能力相同，Prompt 的结构不同，输出质量可能明显不同。

常用策略：

- **Zero-shot**：只给任务说明，不给示例。
- **Few-shot**：提供少量输入—输出示例，引导格式和判断方式。
- **Chain-of-Thought**：要求模型分步骤思考，适合复杂推理；实际系统应注意不要无必要暴露内部思考内容。
- **角色和约束**：明确模型身份、任务目标、输出格式和边界。
- **结构化输出**：要求 JSON、表格或固定字段，方便程序解析。

一个较清晰的 Prompt 通常包含：

```text
角色 / 背景
任务目标
输入数据
约束条件
输出格式
示例（可选）
```

对 Agent 来说，Prompt 还需要告诉模型：有哪些工具、工具参数是什么、什么时候调用工具、什么时候结束任务。

## 八、与开源模型交互的基本流程

调用本地或远程模型，通常需要两个核心对象：

- `Tokenizer`：把文本编码成 Token ID，也负责把生成的 ID 解码回文本。
- `Model`：接收 Token ID，计算下一个 Token 的概率并生成后续内容。

基本流程：

```text
加载 Tokenizer 和 Model
→ tokenizer.encode / apply_chat_template
→ model.generate
→ 截取新生成部分
→ tokenizer.decode
```

生成时常见参数：

- `max_new_tokens`：最多生成多少新 Token。
- `temperature`：调整概率分布的随机程度，越高通常越发散。
- `top_p`：只从累计概率达到阈值的候选中采样。
- `do_sample`：是否启用随机采样。

调参时要理解取舍：温度低通常更稳定、更可复现；温度高可能更有创造性，但也更容易跑题或产生错误。

## 九、模型选型

选择模型不能只看参数量或排行榜，需要根据任务综合权衡：

| 维度 | 需要考虑的问题 |
| --- | --- |
| 能力 | 推理、代码、中文、多语言或多模态是否满足任务 |
| 成本 | API Token 费用或本地 GPU、内存和运维成本 |
| 延迟 | 是否满足实时交互要求 |
| 上下文窗口 | 能否处理长文档、长对话和代码库 |
| 部署方式 | API 方便但数据出域，本地部署隐私和控制力更好 |
| 生态 | SDK、工具调用、微调和社区资料是否成熟 |
| 可定制性 | 是否支持微调、量化和领域适配 |
| 安全性 | 偏见、毒性、幻觉和合规风险 |

一个实用原则是：

```text
简单任务优先考虑成本和速度
复杂推理优先考虑能力和上下文
敏感数据优先考虑隐私和部署方式
稳定生产优先考虑工具调用、生态和可控性
```

## 十、缩放法则与能力涌现

缩放法则描述模型性能与参数量、数据量和计算量之间的关系。通常在一定范围内，增加高质量模型参数、训练数据和计算资源，损失会按可预测趋势下降。

但不是“参数越多就一定越好”。给定计算预算时，模型大小和训练数据量存在更合理的配比。Chinchilla 研究强调，很多模型过去参数过大、训练数据不足，数据效率同样重要。

模型规模增大后，可能出现小模型不明显的能力，例如：

- 指令遵循
- Few-shot / In-context Learning
- 代码生成
- 多步推理
- Chain-of-Thought

这类能力常被称为涌现能力。不过实际应用中不能只依赖“规模会带来能力”，仍需要评测、工具和验证机制。

## 十一、模型幻觉和可靠性

幻觉是指模型生成了与事实、输入或上下文不一致的内容，包括不存在的实体、错误的引用和不忠实的总结。

原因包括：

- 训练数据中存在错误、冲突或偏见。
- 自回归生成的目标是预测高概率 Token，不是内置事实核查。
- 知识可能已经过时。
- 多步推理过程中可能出现逻辑错误。
- 模型在不确定时仍可能给出自信表达。

常用缓解方法：

1. **RAG**：先从外部知识库检索资料，再把资料交给模型生成。
2. **外部工具**：用搜索、计算器、代码执行器或数据库获取实时、精确结果。
3. **多步验证**：让模型检查事实、引用来源或使用第二个步骤复核。
4. **结构化约束**：限制输出格式和可选范围，减少自由编造。
5. **高质量数据和对齐训练**：从训练与微调阶段减少错误和有害输出。
6. **人工审核**：在医疗、金融、法律等高风险场景保留人工确认。

核心原则是：

```text
不要让模型单独承担它不擅长的事实查询、精确计算和高风险决策。
```

## 十二、和 Agent 的关系

第三章的内容直接影响 Agent 设计：

| LLM 基础 | 对 Agent 的影响 |
| --- | --- |
| 自回归生成 | Agent 需要循环和停止条件 |
| Token 与上下文窗口 | 记忆、长对话和工具结果需要管理 |
| Prompt | 决定规划、工具调用和输出格式 |
| 温度和采样 | 影响 Agent 的稳定性和创造性 |
| 幻觉 | 需要 RAG、工具、验证和权限控制 |
| 模型选型 | 决定成本、速度、推理能力和隐私 |
| Decoder-Only | 适合以对话和工具调用为中心的生成式 Agent |

你目前的旅行助手中：

- `llm_client.py` 负责把 Prompt 交给 LLM。
- `prompts.py` 规定 Thought、Action 和 Finish 格式。
- `agent.py` 把模型文本解析成行动。
- `tools.py` 解决模型不能直接获得的实时天气和搜索问题。
- `prompt_history` 把历史 Observation 放回上下文。

## 十四、复习检查点与答案

### 1. 语言模型的基本任务是什么？

语言模型根据已有上下文，计算或预测下一个词元的概率。生成整段文本时，模型会不断把新生成的 Token 加回上下文，再预测下一个 Token。

### 2. N-gram 为什么会有数据稀疏和泛化能力差的问题？

N-gram 依赖语料中的词频统计，没有出现过的组合概率可能为 0；同时它把词当成离散符号，不理解语义相近词之间的关系。即使见过 `agent learns`，也不一定能泛化到 `robot learns`。

### 3. RNN、LSTM 和 Transformer 分别解决了什么问题？

RNN 用隐藏状态保存序列历史，突破了 N-gram 的固定窗口；LSTM 用细胞状态和门控机制缓解 RNN 的长期依赖和梯度消失问题；Transformer 用自注意力直接建模任意位置的关系，并支持并行计算，解决了 RNN 难以并行和长序列效率低的问题。

### 4. 自注意力中的 Q、K、V 分别是什么？

`Q` 表示当前 Token 想查询什么，`K` 表示每个 Token 可被匹配的特征，`V` 表示 Token 实际携带的信息。先用 `QK^T` 计算相关性，再通过 Softmax 得到权重，最后对 `V` 加权求和。

### 5. 为什么需要位置编码？

自注意力可以同时看所有位置，但它本身不天然知道顺序。如果没有位置编码，模型难以区分“猫追狗”和“狗追猫”。位置编码把 Token 的位置信息加入表示，使模型能够理解顺序。

### 6. 为什么现代通用大模型大量采用 Decoder-Only？

Decoder-Only 使用因果掩码，根据左侧上下文预测下一个 Token，训练目标和生成过程一致，结构相对简单，容易扩展到对话、代码、总结和工具调用等统一的生成任务。

### 7. 为什么使用子词 Token，而不是只使用字符或单词？

字符级序列太长，单词级词表太大且难以处理新词、词形变化和中文。子词可以把常见片段合并为一个 Token，又能把生词拆成已知片段，在词表大小和序列长度之间取得平衡。

### 8. Prompt 中为什么要明确角色、任务、约束和输出格式？

模型会根据上下文预测输出，指令越清晰，模型越容易理解目标和边界。明确输出格式还方便程序解析，例如 Agent 可以要求模型只输出工具名和参数，减少额外文本造成的执行错误。

### 9. 如何选择一个用于 Agent 的模型？

不能只看参数量。应综合考虑任务能力、推理质量、中文和代码能力、成本、延迟、上下文窗口、部署方式、隐私、工具调用支持、生态、可微调性和安全性。简单任务可能更重视速度和成本，复杂任务更重视推理与上下文，敏感数据更重视本地部署和隐私。

### 10. 模型为什么会产生幻觉，Agent 应该怎么缓解？

模型的训练数据可能有错误，生成机制只是在预测高概率 Token，并不等于实时查证事实；同时知识可能过时，多步推理也可能出错。Agent 可以使用 RAG、搜索和数据库等外部工具，加入多步验证、结构化输出、权限控制和人工审核，降低幻觉带来的影响。

## 一句话总结

```text
大语言模型通过 Token、Transformer 和预训练获得语言与知识能力，但要成为可靠的 Agent，还需要 Prompt、工具、记忆、验证和执行控制。
```
