# 零钱兑换

LeetCode 322。

## 题意

给定硬币数组 `coins` 和总金额 `amount`，计算凑出该金额所需的最少硬币数。无法凑出时返回 `-1`。每种硬币可以重复使用。

## 我的思路

这是一个完全背包问题，因为每种硬币可以使用多次。

定义：

```text
dp[i]：凑出金额 i 所需的最少硬币数
```

`dp[0] = 0`，表示凑出金额 0 不需要硬币。其他金额初始设为无穷大，表示暂时无法凑出。

## 状态转移

处理面值为 `coin` 的硬币时：

- 不使用当前硬币：保留 `dp[i]`。
- 使用一枚当前硬币：先凑出 `i - coin`，再加一枚硬币，即 `dp[i - coin] + 1`。

所以：

```python
dp[i] = min(dp[i], dp[i - coin] + 1)
```

## 标准模板

```python
def coinChange(coins, amount):
    dp = [float("inf")] * (amount + 1)
    dp[0] = 0

    for coin in coins:
        for i in range(coin, amount + 1):
            dp[i] = min(dp[i], dp[i - coin] + 1)

    return -1 if dp[amount] == float("inf") else dp[amount]
```

## 为什么初始化为无穷大

不能写成：

```python
dp = [0] * (amount + 1)
```

因为这会错误地表示所有金额都可以用 `0` 枚硬币凑出，`min()` 也会一直保留这个错误值。

正确做法是：

```python
dp = [float("inf")] * (amount + 1)
dp[0] = 0
```

无穷大表示不可达，找到真实方案后就会被更小的硬币数量替换。

## 为什么从 `coin` 开始遍历

```python
for i in range(coin, amount + 1):
```

当 `i < coin` 时，当前硬币太大，不能用于凑出金额 `i`。如果从 `1` 开始，`i - coin` 会变成负数，在 Python 中会访问列表末尾，产生错误结果。

## 为什么金额正序遍历

因为硬币可以重复使用。处理 `coin = 2` 时：

```text
dp[2] 可以使用一枚 2
dp[4] 可以使用两枚 2
dp[6] 可以使用三枚 2
```

正序遍历允许后面的状态使用本轮刚更新过的状态，这正是完全背包的特点。

## 示例

```python
coins = [1, 2, 5]
amount = 11
```

最优组合是：

```text
5 + 5 + 1 = 11
```

所以返回 `3`。

如果 `coins = [2]`、`amount = 3`，最终 `dp[3]` 仍为无穷大，因此返回 `-1`。

## 复杂度

- 时间复杂度：O(n × amount)，其中 `n` 是硬币种类数。
- 空间复杂度：O(amount)。

## 与 0/1 背包的区别

| 问题 | 物品使用次数 | 金额遍历方向 |
| --- | --- | --- |
| 分割等和子集 | 每个数字只能一次 | 倒序 |
| 零钱兑换 | 每种硬币可以重复 | 正序 |

记忆：

```text
只能用一次 → 倒序
可以重复用 → 正序
```

## 踩坑点

- `dp[0]` 必须是 `0`，其他状态初始化为无穷大。
- 内层循环从 `coin` 开始，不能从 `1` 开始。
- 无法凑出时要把无穷大转换为 `-1`。
- `amount == 0` 时，`dp[0]` 已经保证返回 `0`。
