# 零钱兑换 II

LeetCode 518。

## 题意

给定不同面额的硬币 `coins` 和总金额 `amount`，计算凑出该金额的组合数。如果无法凑出，返回 `0`。

每种硬币可以重复使用，但不同顺序的排列算作同一种组合。

例如：

```text
1 + 2 和 2 + 1 属于同一种组合
```

## 我的思路

这道题和《零钱兑换》一样属于完全背包，因为硬币可以重复使用；但目标从“最少硬币数”变成了“组合数量”。

## 状态定义

```text
dp[i]：使用已经遍历过的硬币，凑出金额 i 的组合数
```

初始化：

```python
dp = [0] * (amount + 1)
dp[0] = 1
```

`dp[0] = 1` 表示凑出金额 `0` 有一种方式：一个硬币都不选。这个初始方案可以帮助后续推导出只使用一枚硬币的组合。

## 状态转移

遍历当前硬币 `coin` 时，凑出金额 `i` 的新组合可以这样得到：

```text
先凑出 i - coin
再加入一枚 coin
```

因此：

```python
dp[i] += dp[i - coin]
```

含义是：原来凑出 `i` 的组合继续保留，再加上使用当前硬币得到的新组合。

## 标准模板

```python
def change(amount, coins):
    # dp[i]：凑出金额 i 的组合数
    dp = [0] * (amount + 1)
    dp[0] = 1

    for coin in coins:
        for i in range(coin, amount + 1):
            dp[i] += dp[i - coin]

    return dp[amount]
```

## 为什么外层必须遍历硬币

代码顺序是：

```python
for coin in coins:
    for i in range(coin, amount + 1):
```

外层先固定硬币种类，内层再逐步计算金额，这样每种组合会按照固定的硬币顺序被统计一次。

例如 `coins = [1, 2]` 时：

```text
1 + 2
```

会被统计，但不会再次把：

```text
2 + 1
```

当成另一种组合。

如果反过来写：

```python
for i in range(1, amount + 1):
    for coin in coins:
```

就可能分别统计不同的硬币使用顺序，这更接近“排列数”问题。

记忆：

```text
组合数：硬币在外层
排列数：金额在外层
```

## 示例

```python
amount = 5
coins = [1, 2, 5]
```

可以组成：

```text
1 + 1 + 1 + 1 + 1
1 + 1 + 1 + 2
1 + 2 + 2
5
```

所以返回：

```text
4
```

## 和零钱兑换的区别

| 题目 | `dp` 含义 | 转移方程 |
| --- | --- | --- |
| 零钱兑换 | 凑出金额所需的最少硬币数 | `min(dp[i], dp[i - coin] + 1)` |
| 零钱兑换 II | 凑出金额的组合数 | `dp[i] += dp[i - coin]` |

两道题都使用完全背包的正序遍历，但优化目标不同。

## 复杂度

- 时间复杂度：O(n × amount)，其中 `n` 是硬币种类数。
- 空间复杂度：O(amount)。

## 踩坑点

- `dp[0]` 必须初始化为 `1`，不是 `0`。
- `n = len(coins)` 是硬币种类数，不能用来创建金额 DP 数组。
- DP 数组长度应该是 `amount + 1`。
- 因为硬币可以重复使用，金额要正序遍历。
- 要统计组合数，必须让硬币在外层，避免把不同顺序重复计算。
- 这道题返回的是组合数量，不是最少硬币数。
