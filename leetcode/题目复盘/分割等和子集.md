# 分割等和子集

LeetCode 416。

## 题意

给定一个只包含正整数的非空数组，判断是否可以将数组分割成两个子集，使两个子集的元素和相等。

每个数字只能使用一次。

## 我的思路

如果数组总和是奇数，就不可能分成两个相等的整数和，直接返回 `False`。

如果总和是偶数，只需要判断能否从数组中选出若干数字，使它们的和等于：

```python
target = sum(nums) // 2
```

这可以转化成一个 0/1 背包问题：每个数字是一个物品，每个数字只能选择一次，背包容量是 `target`。

## 状态定义

```text
dp[i]：只使用当前已经遍历过的数字，能否凑出总和 i
```

其中：

```python
dp[0] = True
```

表示一个数字都不选时，可以凑出总和 `0`。

## 状态转移

遍历到数字 `num` 时，凑出总和 `i` 有两种情况：

1. 不选择 `num`，原来 `dp[i]` 已经为 `True`。
2. 选择 `num`，只要之前能够凑出 `i - num`，加上 `num` 后就能凑出 `i`。

因此：

```python
dp[i] = dp[i] or dp[i - num]
```

## 标准模板

```python
def canPartition(nums):
    total = sum(nums)

    if total % 2 != 0:
        return False

    target = total // 2
    dp = [False] * (target + 1)
    dp[0] = True

    for num in nums:
        # 从后向前遍历，保证每个数字只使用一次
        for i in range(target, num - 1, -1):
            dp[i] = dp[i] or dp[i - num]

            if dp[target]:
                return True

    return dp[target]
```

## 为什么要倒序遍历

```python
for i in range(target, num - 1, -1):
```

倒序遍历可以保证当前数字 `num` 在这一轮最多被使用一次。

当计算 `dp[i]` 时，`dp[i - num]` 仍然是加入当前 `num` 之前的状态，因此它不会包含当前数字。这样更新后的 `dp[i]` 至多使用当前 `num` 一次。

如果改成正序遍历，当前轮刚更新的状态可能马上被后面的计算使用，导致同一个数字被重复使用。

例如：

```text
nums = [3]
target = 6
```

正序处理 `3` 时：

```text
先得到 dp[3] = True
再使用 dp[3] 推出 dp[6] = True
```

这相当于把数组中唯一的 `3` 使用了两次，是错误的。倒序遍历时先计算 `dp[6]`，此时 `dp[3]` 仍然是旧状态，就不会发生重复使用。

## 示例

```python
nums = [1, 2, 4, 5]
```

数组总和为 `12`，目标值为：

```text
target = 12 // 2 = 6
```

可以选择：

```text
2 + 4 = 6
```

剩余数字 `1 + 5 = 6`，因此可以分割成两个和相等的子集，返回 `True`。

## 提前返回

如果在遍历过程中发现：

```python
dp[target] == True
```

说明已经找到一个和为 `target` 的子集。剩余数字的总和也必然是 `target`，因此可以直接返回 `True`，不需要继续遍历。

## 复杂度

- 时间复杂度：O(n × target)，其中 `n` 是数组长度。
- 空间复杂度：O(target)，使用一维 DP 数组。

## 踩坑点

- 总和为奇数时，答案一定是 `False`。
- `dp[i]` 表示能否凑出和 `i`，不是恰好选择了多少个数字。
- 这是 0/1 背包，每个数字只能使用一次，所以容量必须倒序遍历。
- `dp[0]` 必须初始化为 `True`，否则无法从空集合开始推导其他状态。
- `num > target` 时，该数字无法参与凑出目标值，内层循环不会执行。
- `dp[target]` 变成 `True` 后可以提前返回。
